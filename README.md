# 하루하루 · HaruHaru 2.0

Локальний PWA для вивчення корейської українською: конспекти, словник, картки, вправи, календар, XP та маскот Хару. Без обов’язкової авторизації й власного backend.

## Запуск на іншому ПК

Потрібні **Node.js 24 LTS** (або сумісний Node 22.12+) і **pnpm 11**. Установіть Node зі звичайним додаванням у PATH, потім за потреби встановіть pnpm:

```sh
npm install --global pnpm@11
```

Завантажте/клонуйте весь вихідний проєкт, перейдіть у папку `haruharu` й виконайте:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Відкрийте адресу, яку покаже Vite, зазвичай `http://localhost:5173/`.

Якщо pnpm повідомляє про заблокований сценарій esbuild:

```sh
pnpm approve-builds
```

Дозвольте esbuild та виконайте запропоновані pnpm дії. У поточному `pnpm-workspace.yaml` значення allowBuilds для esbuild залишилося незавершеним; докладніше — [PROJECT_STATUS.md](PROJECT_STATUS.md).

## Збірка

```sh
pnpm build
pnpm preview
```

Для GitHub Pages репозиторію `haruharu`:

```sh
pnpm exec vite build --mode pages
```

Для іншої назви репозиторію:

```sh
pnpm exec vite build --base=/назва-репозиторію/
```

Результат — `dist/`. HashRouter підтримує вкладені екрани без серверних rewrite. PWA перевіряють на production-збірці; iPhone потребує доступної HTTPS-адреси, а не localhost іншого комп’ютера. Команди самі не публікують проєкт.

## Змінні середовища

Для звичайного локального навчання змінні не потрібні. Для Google Calendar створіть `.env.local` за зразком `.env.example`:

```dotenv
VITE_GOOGLE_CLIENT_ID=
```

Задайте власний OAuth Web Client ID та перезапустіть Vite; для production — зберіть повторно. Google Calendar API й дозволені origins налаштовуються вручну: [інструкція](docs/CALENDAR_INTEGRATION.md). Client Secret, паролі та access token у файли/код не додавайте. Авторизація виконується у вікні Google, токен зберігається лише в пам’яті вкладки.

## Перенесення навчальних даних

На старому ПК відкрийте **Налаштування → Резервна копія → Експорт**. На новому — імпортуйте JSON із попереднім переглядом. IndexedDB не зберігається в Git і не переноситься простим копіюванням проєкту. Імпорт додає матеріали; повторне імпортування створює копії. Вхід у Google та підписки потрібно підключити знову. Приватну резервну копію не завантажуйте в публічний репозиторій.
