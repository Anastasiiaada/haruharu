# HaruHaru — стан проєкту

Зафіксовано 12 листопада 2026 року для продовження на іншому ПК. Версія package.json — **2.0.0**. Цей документ підготовлено швидким переглядом; під час цього завдання тести, збірка, встановлення та запуск не виконувалися.

## Реалізовано

- React/TypeScript/Vite PWA українською, адаптивний інтерфейс, світла/темна теми, HashRouter, підготовка GitHub Pages.
- Головна зі статистикою, серією днів, щоденною ціллю та прогресом рівня.
- Конспекти: Tiptap, таблиці, категорії, пошук, CRUD, JSON-імпорт/експорт із перевіркою та переглядом.
- Словник: слова, переклади, приклади, категорії, пошук, вивченість, CRUD та JSON.
- Картки: два напрямки, інтервальне повторення, 3D flip і свайпи відкритої відповіді.
- Практика: переклад, написання, пропуски, частки, речення, диктанти; помилки, іспити та статистика.
- Корейський TTS: лише доступний корейський голос, швидкості 0.75/1/1.25, повтор і зупинка, робота з асинхронним списком голосів.
- Календар: місяць/тиждень/день, локальні події та серії, уроки, дедлайни, заплановані слова, Europe/Kyiv.
- Код Google read-only інтеграції через GIS/Calendar API: вибір джерел, пагінація, повторення, кеш, відключення та повторний вхід.
- Apple/інші календарі: ICS-імпорт/експорт, публічні підписки за дозволеного CORS, дедуплікація UID/входжень.
- Корейські свята 2026–2027 з явними перевіреними датами, традиціями, словами та TTS.
- Дзвіночок, unread-лічильник, IndexedDB inbox, налаштування нагадувань, добровільні браузерні сповіщення без сервера push.
- Help Center із 12 темами, пошуком, FAQ і прихованим технічним розділом; тур і вікно «Що нового?» з історією.
- Редизайн 2.0: новий Hero, пастельна система, SVG-маскот Хару, Motion, тости, скелетони, конфеті, дружній зворотний зв’язок.
- XP за збережені дії, рівні, цілі 5/10/20, значки, оригінальні необов’язкові Web Audio звуки.
- IndexedDB v3: міграція без очищення; резервні копії матеріалів, прогресу, календаря, XP й значків. Lazy-loading сторінок та ефектів.

## Поточний етап / у роботі

Реалізація 2.0 доведена до етапу локального коду та автоматичних перевірок у попередній сесії. Активних фонових задач із розробки немає. Наступний етап — ручна візуальна перевірка, реальний iPhone/PWA та подальше UX-полірування. Нових результатів перевірок під час підготовки цих документів немає.

Попередньо повідомлені результати: TypeScript, **65 тестів**, production build і Pages build були успішними. На іншому ПК це ще потрібно відтворити; стан його середовища невизначений.

## Залишилося

1. Перевірити UI на 320–430 px, desktop, темну тему, тур, модальні вікна, swipe, reduced motion та фактичне відсутнє накладання Hero.
2. На реальному iPhone перевірити встановлення, офлайн, оновлення між двома production-версіями, TTS, звукові ефекти та дозволи сповіщень.
3. Виміряти продуктивність; 60 FPS наразі лише ціль, не підтверджений результат. За потреби зменшити початковий bundle і впорядкувати накопичені CSS-перевизначення.
4. Налаштувати власний Google OAuth Client ID і пройти живий вхід/синхронізацію, перевірити завершення токена та зміну акаунта.
5. Перевірити реальні ICS-файли Apple та публічні підписки на потрібних джерелах.
6. Додати справжні матеріали викладача замість демонстраційних A1; надалі оновлювати підтверджені роки свят.
7. Приватний iCloud/CalDAV, backend, push із закритої PWA і двостороння синхронізація не реалізовані. Вони потребують окремого рішення, а не лише налаштування frontend.

## Відомі обмеження та питання середовища

- Браузерний host у попередніх сесіях був недоступний: немає підтвердженої візуальної перевірки, скріншотів або вимірювань FPS.
- Збірка повідомляла про головний JS chunk понад 500 kB; це попередження, не провал збірки. Точний розмір після наступних змін невизначений.
- `pnpm-workspace.yaml` містить `allowBuilds.esbuild: set this to true or false`. Попереднє встановлення завершувалося повідомленням ERR_PNPM_IGNORED_BUILDS, хоча залежності були доступні. На новому ПК може знадобитися `pnpm approve-builds` і дозвіл esbuild; конфігурацію в цьому документаційному завданні не змінено.
- У попередньому середовищі Node не був у PATH; новий ПК повинен мати звичайне встановлення Node/pnpm. Локальні абсолютні шляхи попереднього ПК використовувати не потрібно.
- Голос ko-KR та його офлайн-доступність залежать від пристрою. Сповіщення перевіряються у відкритому застосунку/при поверненні, без гарантованого фонового push.
- ICS URL може блокуватися джерелом через CORS; приватні URL та пароль Apple ID у frontend не вводити.
- XP за старі відповіді автоматично не додаються. Звичайний імпорт матеріалів створює копії; повторний імпорт журналу нагород не подвоює його записи.
- Дані IndexedDB не переносяться разом із папкою чи GitHub-репозиторієм. Перед переходом експортуйте JSON-backup на старому ПК.
- Стан віддаленого репозиторію та фактичної публікації невизначений. Під час роботи агента commit/push/deploy не виконувалися.

## Google Calendar — ручне налаштування

Реальний Client ID у документацію не записаний; жива авторизація не перевірена. Потрібні:

1. Google Cloud проєкт з увімкненим Google Calendar API.
2. Google Auth Platform/consent screen, тестові користувачі для Testing та scope `https://www.googleapis.com/auth/calendar.readonly`.
3. OAuth client типу Web application; Authorized JavaScript origins: `http://localhost:5173` та `https://ВАШ-ЛОГІН.github.io` без `/haruharu/`. Для поточного GIS popup redirect URI не потрібен.
4. Локальний `.env.local` з `VITE_GOOGLE_CLIENT_ID`; перезапуск Vite або нова production-збірка. Client Secret не потрібен і заборонений у frontend.
5. Вхід через «Календар → Джерела → Підключити Google Calendar». Access token — лише в пам’яті, тому після нового відкриття/закінчення сеансу потрібне повторне підключення.
