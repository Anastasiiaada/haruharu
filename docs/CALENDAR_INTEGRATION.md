# Календар HaruHaru 1.1

## Що працює локально

Місяць, тиждень, день; події уроків, домашніх завдань, повторень і власних планів; щоденні/щотижневі повторення з кінцевою датою (до 10 років). Редагування або видалення повторюваної локальної події застосовується до всієї серії. Час Europe/Kyiv через IANA/Intl (Luxon), тож час уроку зберігається при переходах DST; неіснуючий час відхиляється. Для двозначного часу восени краще обирати час поза годиною переходу. Дата закінчення події на весь день є виключною, згідно з iCalendar.

Нагадування з’являються у внутрішньому центрі сповіщень під час відкритого застосунку, при поверненні та раз на хвилину. Пропущені за останню добу також потрапляють до центру. Це не push і не гарантія сигналу при закритій PWA. Системні дозволи й мікрофон не потрібні.

## Google Cloud: ручне налаштування

1. Створіть проєкт у Google Cloud Console, увімкніть **Google Calendar API**.
2. Налаштуйте Google Auth Platform: Branding, Audience та Data Access. Для зовнішнього застосунку в режимі Testing додайте свою пошту до Test users. Для загальнодоступного застосунку Google може вимагати верифікацію доступу до користувацьких даних.
3. Створіть OAuth client типу **Web application**. Додайте Authorized JavaScript origins: `http://localhost:5173` та `https://ВАШ-ЛОГІН.github.io`. Origin не містить `/haruharu/` чи hash-маршрутів. Для GIS token popup redirect URI цього застосунку не потрібен. В iPhone використовуйте той самий HTTPS origin, який зареєстровано.
4. Скопіюйте `.env.example` у `.env.local`. Задайте `VITE_GOOGLE_CLIENT_ID=...apps.googleusercontent.com`. Це публічний Client ID. **Client Secret та приватні ключі не додавайте**. Перезапустіть Vite; для production зберіть повторно. Для Pages значення має бути в build environment, а не у runtime.
5. Відкрийте Календар → Джерела → Google → Підключити. У власному вікні Google надайте лише `https://www.googleapis.com/auth/calendar.readonly`, потім виберіть календарі.

Токен живе лише в пам’яті вкладки; не в IndexedDB/localStorage, JSON, URL або service worker. Після перезавантаження чи завершення терміну дії потрібно натиснути підключення знову. GIS popup запускається безпосередньо натисканням після завантаження скрипту. Немає refresh token або прихованої авторизації. Під час повернення у відкриту вкладку кеш оновлюється, якщо токен ще чинний; нове відкриття без токена показує кеш і запит повторного входу. Фонової синхронізації закритої PWA немає.

Calendar API: повне завантаження вікна від початку минулого року до початку року після наступного. `singleEvents=true` розгортає повторення та винятки, `showDeleted=true` повертає скасовані входження. Після успіху всіх сторінок snapshot конкретного Google-джерела атомарно замінюється: зниклі події прибираються лише з його кешу. При помилці кеш не очищується; є повтори для 429/5xx та ручне Оновити. Ідентифікатор — account/calendarId/eventId. За межами вікна події Google не завантажені, це зазначено в інтерфейсі. Зміна акаунта приховує попередні джерела, зберігаючи кеш. Відключення очищує токен, приховує Google-джерела та за наявності токена викликає офіційне revoke; без токена дозволи можна прибрати в Google Account → Third-party connections.

Реальний OAuth-прохід не перевірений без Client ID та дії власника акаунта.

Офіційні джерела: [GIS token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [Events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list).

## Apple Calendar та ICS

Застосунок не має прямого доступу до календаря iPhone. Експортуйте календар на Mac або отримайте ICS-файл іншим способом; завантажте у розділі джерел. Перед збереженням видно список подій. Для оновлення імпортуйте файл у те саме джерело. Усі календарі, що мають спільні UID та recurrence-id, відображаються один раз, Google має пріоритет. Назва й час не використовуються як ідентичність, щоб не приховати різні реальні події. Якщо експортер змінює UID, автоматично довести тотожність неможливо: приховайте дублююче джерело.

ICS розбирається ical.js: RRULE/RDATE/EXDATE, RECURRENCE-ID, перенесені й скасовані входження, дата на весь день, VTIMEZONE, UTC та IANA TZID. Floating time без зони інтерпретується як Europe/Kyiv; невідома зона без VTIMEZONE відхиляється. Ліміти: 5 МБ, 5000 подій/входжень, 25000 кроків розгортання; повторення частіше одного дня не підтримуються. Такі файли відхиляються з поясненням, не імпортуються частково. Вікно перегляду обчислюється з оригінального ICS, тож імпортовані повторення доступні й офлайн.

Експорт `haruharu.ics` включає лише локальні події HaruHaru, стабільні UID, RRULE, нагадування та VTIMEZONE Europe/Kyiv із сучасними правилами DST. Відкрийте файл у Calendar на Mac або передайте/імпортуйте його на iPhone підтримуваним вашим пристроєм способом. Зміни в Apple після експорту автоматично назад не повертаються. Поведінка повторного імпорту файлу залежить від клієнта.

Публічний HTTPS/webcal ICS URL можна додати лише після явного підтвердження, що він публічний. URL не повинен містити credentials, query чи fragment. Публічний URL зберігається лише на пристрої в джерелі; не в коді; не входить до JSON-backup. Секретний або приватний URL не вводьте. Запит без cookies, без referrer; сервер має дозволяти CORS. Дані оновлюються при відкритті/поверненні та кнопкою Оновити, без обходу CORS і без стороннього proxy. Якщо iCloud не дозволяє CORS, завантажте ICS та імпортуйте файл. URL публічного iCloud — посилання доступу для будь-кого, хто його має; для чутливих подій використовуйте файловий імпорт.

## Архітектура приватного iCloud (ще не реалізована)

GitHub Pages не може безпечно виконувати приватну CalDAV-інтеграцію. Майбутній окремий backend має:

- Приймати лише окремий пароль застосунку Apple (якщо обраний офіційно підтримуваний CalDAV-процес цього вимагає), ніколи основний пароль Apple ID. Альтернативну авторизацію слід використовувати лише якщо Apple надає її конкретному інтегратору.
- Зберігати секрет зашифрованим у серверному сховищі секретів; видавати frontend лише HttpOnly/Secure/SameSite session cookie або короткочасну сесію. Не повертати credentials, приватний CalDAV URL чи токен підписки у frontend/логи.
- Виконувати discovery principal/home-set, REPORT calendar-query/sync-collection із sync-token та ETag, розгортати recurrence та вести канонічні UID/RECURRENCE-ID; мати відключення, видалення секрету, розмежування власників і мінімальний read-only доступ.
- Для URL-проксі мати захист SSRF: allowlist, заборона private/link-local IP, перевірка DNS та кожного redirect, ліміти розміру й часу, заборона логування приватних URL.
- Не надавати запис чи двосторонню синхронізацію до окремої реалізації, конфліктної моделі та перевірки на реальному iCloud.

У цій версії немає форми Apple ID/password і немає прихованого proxy. [Підписки Apple](https://support.apple.com/en-ca/102301).

## Свята

Вбудований перевірений набір 2026–2027: фіксовані, місячні, перенесені вихідні й виборчий день 2026, а також оновлені День праці/Конституції. Місячні дати не розраховуються. Дати без часу трактуються як корейські календарні дні без зсуву в Київ. Неділі окремими святковими картками не дублюються. За межами цих років шар порожній і показує попередження. Нові разові державні вихідні потребують оновлення набору, автоматичного державного API немає. Джерела та дата перевірки відображені в Допомозі.

## Перевірка

`npm run typecheck`, `npm test`, `npm run build`. OAuth і реальний iCloud потребують конфігурації й ручного тесту. PWA офлайн показує локальні події, ICS, свята та кеш Google; оновлення зовнішніх календарів потребує мережі.
